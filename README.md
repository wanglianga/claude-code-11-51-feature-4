# 经营指标语义层与自助分析平台

面向连锁零售集团的经营指标语义层与自助分析平台。解决总部、区域、门店三方对"本月销售额""同店增长"口径不一致的问题：通过集中语义定义、版本化运行、血缘下钻，让经营会上同名指标数字一致且可解释。

## 核心能力

- **集中语义定义**：指标用受控 DSL（表达式 AST）定义，表达来源字段、过滤、分组、聚合、四则组合、其他指标引用，**不接受任意 SQL**，也不只存一段口径说明
- **定义校验**：先识别引用环路，再校验金额、数量、比例、时间粒度；不同币种未经显式换算不能相加，门店日指标不能与门店月指标逐行相乘
- **运行引擎**：固定引用定义版本；标记数据截止点与覆盖范围，**不把未到数据当成零销售**；比率上卷时重新汇总分子分母
- **同店队列**：按两个比较期共同满足的营业状态与覆盖规则确定，跨期新开、闭店、缺资料门店各自说明，不把缺失期销售额填零后加入增长率
- **迟到退款**：影响计算生成新运行候选，已发布报表继续引用原运行，经营负责人决定是否发布更正
- **血缘下钻**：每个结果格可展开参与记录、过滤排除及最终算式
- **客单金额分布**：订单金额先编译为"每订单键一个观察值"（多行拆单合计、多渠道支付校验、重复回执去重、撤销/未支付排除、部分退款按截止点重算净额、状态不定单列待核），再按门店 × 营业周 × 业态维度输出中位数 / P90 / 高额占比；**精确排序**与**可合并近似摘要（t-digest，附严格排名误差界）**双路线同源对照，样本不足或误差超限自动降级且**不以均值替代**；迟到退款/更正/去重决议只局部重建受影响订单集合与摘要版本，发布快照保持当时样本与数值

## 技术栈

- **后端**：Spring Boot 3.5 + Java 21 + Spring Data JPA + Flyway
- **前端**：Vue 3 + Vite + Element Plus
- **数据库**：PostgreSQL 16
- **部署**：Docker Compose 一键启动

## 指标 DSL 说明

指标定义是 JSON 表达式树（AST），节点类型：

| 节点 | 说明 | 示例 |
|------|------|------|
| `field` | 取源字段 | `{"op":"field","source":"orders","field":"amount"}` |
| `const` | 常量 | `{"op":"const","value":0.05}` |
| `agg` | 聚合 | `{"op":"agg","measure":"sum","expr":{...},"filter":[...],"by":["store_id"]}` |
| `arith` | 四则运算 | `{"op":"arith","operator":"sub","left":{...},"right":{...}}` |
| `convert` | 币种换算 | `{"op":"convert","expr":{...},"fromCurrency":"USD","toCurrency":"CNY","rate":7.1}` |
| `ref` | 引用其他指标 | `{"op":"ref","metric":"gross_sales"}` |
| `cohort` | 同店增长 | `{"op":"cohort","base":{...},"compare":"prev_period","cohortKey":"store_id"}` |

**示例：净销售额**
```json
{
  "op": "arith", "operator": "sub",
  "left": {"op": "ref", "metric": "gross_sales"},
  "right": {"op": "ref", "metric": "refund_total"}
}
```

**校验规则**：
- 引用环路检测（DFS 三色标记）
- 金额/数量/比例类型检查
- 不同币种未经 `convert` 换算不能相加
- 门店日指标不能与门店月指标逐行相乘
- 金额与金额不能相乘（量纲错误）

## 客单金额分布查询

平均客单价平稳可能掩盖两种完全不同的结构（低额日常单增多 vs 少数大额团购拉高总额）。分布查询在订单级指标结果之上，按**门店 × 营业周（ISO 周）× 用户选择的业态维度（渠道）**输出**中位数、P90、高额订单占比**，每项都标明**订单总体、退款状态截止点、有效样本数、覆盖范围**。

### 1. 订单金额编译（统计前的唯一口径）

一张订单可能拆成多行商品、多个支付渠道、多条状态回执。统计前必须按**稳定订单键**（order_id）编译为**一个金额观察值**（`OrderAmountCompiler`，纯函数、可完全复算）：

| 情形 | 规则 |
|------|------|
| 多行商品拆单 | 有订单行时毛额 = 行金额合计（`amount_source=lines`），否则取订单头金额 |
| 多个支付渠道 | 支付流水按订单键汇总校验；无订单行仲裁且支付合计与订单金额不一致 → **待核** |
| 重复回执 | 同一 `receipt_id` 只计最早到达的一条，**不复制订单** |
| 撤销 / 未完成支付 | `void/cancelled/unpaid` → **排除**，不混入已完成交易 |
| 部分退款 | 按**退款状态截止点**重算净额：`net = gross − Σ(refunded_at ≤ cutoff)` |
| 最终状态不定 | 回执冲突（同一时刻多种最终状态）、退款超过订单金额 → **待核**，单列不进入样本 |
| 零金额 | 净额为 0 的已完成订单（全额退款/全额抵扣）作为 **0.00 观察值计入分布** |
| 外币订单 | 未经换算不混入 CNY 分布 → **排除** |

编译按版本进行（`dist_compile` 记录退款状态截止点），观察值按（订单键 × 编译版本）留存，查询取每键最新版本。**样本守恒**：订单总体 = 有效样本 + 待核 + 排除。

### 2. 两条查询路线（同一分位数定义）

**分位数定义（全平台唯一约定）**：升序样本 x(0..n-1)，`h = q·(n-1)`，线性插值 `v = x(i) + f·(x(i+1) − x(i))`（type-7，同 Excel PERCENTILE.INC）。中位数 = q(0.5)，P90 = q(0.9)。高额占比 = `net ≥ 阈值` 的样本数 / 有效样本数（阈值查询参数，默认 1000）。

| | 精确路线 `exact` | 近似路线 `approx` |
|---|---|---|
| 做法 | 从订单观察值精确排序计算 | 按 门店×营业周×渠道 预建 **t-digest 摘要**（k1 尺度，δ=100），查询时向上合并 |
| 过滤灵活性 | 任意过滤（渠道、金额区间…） | 仅支持的维度/过滤（渠道）；**不支持的过滤维度假称精确是禁止的** → 自动降级精确重算并显式标记 |
| 成本 | 数据量大、并发切片多时排序与内存开销大 | 扫描快、存储有界（质心 ≤ ~50 个/格） |
| 误差 | 0 | 每个结果附**严格排名误差界** `[rankLo, rankHi]`（由质心样本覆盖范围 [min,max] 推出，真实排名必在界内） |

**降级规则**：有效样本 < 最小样本数（默认 10）→ 标出 `unavailable_small_sample`，分位数返回空，**不静默返回均值**；摘要误差界超过展示要求（`maxRankError`，默认 0.05）→ 自动降级为精确重算并标记 `degraded`；近似值与精确值的对照验证见 `scripts/verify.sh` 第 13 节与 `TDigestTest`。

### 3. 同源与修订

交易金额编译、分布摘要构建、查询筛选、结果发布引用**同一退款状态截止点与同一编译规则**。迟到退款、订单更正、去重决议只**重建受影响订单集合与摘要版本**（局部重建，其它范围保持原版本）；已发布快照（`dist_publication`）保持发布时的样本与数值，`/compare` 仅用于展示漂移、不回写。

### 4. API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/dist/compile` | 全量编译；body 带 `orderKeys` 时局部重建 |
| POST | `/api/dist/query` | 分布查询：`from/to/storeIds/dims/filters/route/highThreshold/minSample/maxRankError` |
| GET | `/api/dist/orders` | 当前观察值（`state=pending` 为待核清单） |
| GET | `/api/dist/summaries` | 近似摘要（含编译版本，验证局部重建） |
| GET | `/api/dist/compiles` | 编译版本历史（含退款截止点） |
| POST | `/api/dist/revisions/late-refund` | 迟到部分退款 → 局部重建 |
| POST | `/api/dist/revisions/correction` | 订单更正（金额/状态）→ 局部重建 |
| POST | `/api/dist/revisions/dedup` | 订单去重决议（重复键并入规范键）→ 局部重建 |
| POST | `/api/dist/publications` | 发布快照（冻结当时样本与数值） |
| GET | `/api/dist/publications/{id}/compare` | 快照 vs 当前重算漂移对比（快照不回写） |

前端「分布查询」页提供查询面板、结果表（含误差界与降级标记）、待核订单、观察值明细、发布快照与数据修订操作。
